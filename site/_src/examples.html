The same library, {{examples.n}} different fields

A trial, a wheat field, a reactor, a nature reserve and a checkout page are the same mathematics wearing different words. That is the whole reason axiom's core has no domain in it — the nouns are treatment, dose, unit, outcome and covariate, and marketing is one adapter rather than the subject. These {{examples.n}} walkthroughs are the argument for why that was worth doing.

Each one is a worked argument rather than a listing: {{examples.total_steps}} steps in total, every one saying why it is the necessary step and what was rejected to get there, with {{examples.total_figures}} charts and the exact code and output each step produced. Every one runs against a synthetic world whose truth is known, so the numbers can be checked rather than admired. Together they are {{examples.total_lines}} lines and take {{examples.total_seconds:.0f}} seconds.

How these pages are built

Nothing here is transcribed. Each script narrates itself through examples/_walkthrough.py, and the site build runs it with a capture flag set, so the steps, the tables, the readouts and every chart series on these pages are the record of a real run. The code shown against a step is sliced out of the source file by line number — the code that ran between that step's heading and the next, with only each figure's caption text elided, since the page shows it with the figure instead. Every page carries the unedited file at the bottom. A broken example fails the build rather than shipping stale prose.

Writing another one

Keep the shape: a docstring that states the field's question in that field's own terms, a synthetic world with a known truth, then w.step(title, why=…, instead=…) for each move — the instead is the part readers get nowhere else, so it has to be the alternative a reasonable person would really have reached for. Close with w.finding(…) saying what the numbers showed. Then add it to the table in examples/README.md.
