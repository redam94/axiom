How to read this

Layers, and why they matter to you

foundation

core, data, io. Specs, dimensions, intervals, panels, and the analysis round-trip. Pure numpy / scipy / pandas / pydantic. If you only ever import these, axiom is a very small dependency.

sampler seam

infer. The one place an optional dependency is allowed to live. Laplace works with no extras; NumPyro and PyMC sit behind pip install "axiom[numpyro]" and pip install "axiom[pymc]", and four NUTS samplers agree to within 0.12 posterior standard deviations over one shared log density.

domain

identify, estimands, surface, sim. The causal and functional vocabulary — graphs, nine-facet estimands, response kernels, and the synthetic worlds that make every claim in the test suite checkable against a known truth.

the pillars

design, calibrate, meta. Peers, with no cross-imports except design ← surface and calibrate ← estimands. You can use any one of them without dragging in the others.

composition

diagnose, build, adapters, viz, report. Everything that composes the layers below — model checking, fluent builders, the domain adapters, plots, and templated HTML / PPTX / PDF reports.

Imports point down only

A contract test walks the import graph and fails the build if an arrow ever points back up. That is what keeps the foundation usable on its own and lets the pillars be adopted one at a time.

Getting the full documentation

This page is a map, not a reference manual. The Sphinx documentation — signatures, docstrings, and the notebook series for each subpackage — builds from the repository with make docs, and every subpackage’s API page links its own notebook series.

shell 
git clone https://github.com/redam94/axiom
cd axiom
uv sync --group dev

make docs        # Sphinx, builds with zero warnings
make notebooks   # execute every notebook under nbs/
make gates       # the twelve contract tests

Where to start reading code

nbs/end-to-end Five notebooks, one per pillar. The shortest path from nothing to a working analysis. 5
nbs/case-studies The HYPER-3 trial, worked over one synthetic world. 6
docs/plan The charter, architecture, porting ledger, roadmap, and the contracts-and-testing rules the build enforces. 6
docs/notes Numbered design decisions, written as the work happened — including why a number deliberately changed from its parent. 8
